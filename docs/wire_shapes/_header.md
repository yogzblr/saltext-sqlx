# Wire shapes

What the databases and drivers actually do, observed by task T1 on 2026-10-29. Rule R18: nothing here is taken from
documentation. A case that could not be executed is marked **NOT RUN** with the reason; it is never filled in.

Generated by `scripts/probes/render_wire_shapes.py` from the JSON in `docs/wire_shapes/` (raw output of
`scripts/probes/probe_<dialect>.py`). Re-run the probes and the renderer to refresh it.

Environment: Ubuntu 24.04 x86_64, Python 3.13.16, no Docker images (registry access is blocked, section 0), databases
started natively by `tests-support/up.sh`. Accounts: `ro` (SELECT only) and `rw` (DML) on schema `scratch`, over TCP on
127.0.0.1. Statements are issued the way the module will issue them: caller SQL through `text()` with binds; the
module's own statements through `exec_driver_sql()`; one engine per run with `NullPool`.

How to read the exception columns. *SQLAlchemy exception* is `type(e)` of what `engine.connect()` / `conn.execute()`
raised, in `sqlalchemy.exc`; "(not SQLAlchemy)" means the exception reached the caller unwrapped. *Driver exception*
is `type(e.orig)`. *Fields* lists the attributes the driver exception carries (`args(...)` are the positional
argument types; `diag{...}` is psycopg's diagnostics object; `args[0]{...}` is oracledb's error object). *Password in
exception text* is true if the account password appeared in `str(e)`, `repr(e)`, `repr(e.orig)`, `repr(e.orig.args)` or
the formatted traceback (wrong-password case: the wrong password). *SQL text in `str(exc)`* is whether SQLAlchemy's own
`str()` of the exception contains the statement (it appends `[SQL: ...]`).
