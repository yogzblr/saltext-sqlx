Connection parameters in the call now work with no minion configuration (SPEC decision D16, owner decision 2026-11-01), as in Salt's own `postgres.psql_query`: `dialect`, `driver`, `host`, `port`, `database`, `username` and `password` (a literal or an `sdb://` reference) on `query`, `check_query_result`, `check_row_count`, `ping`, `table_list` and `psql_query`, for PostgreSQL, MySQL/MariaDB, Oracle and SQL Server, with or without `profile=`. Before this change `sqlx:_policy:allow_call_params` was off by default and such calls were `[E_OPTION_UNKNOWN]`. Set `sqlx:_policy:allow_call_params: []` to get the old profile-only behaviour; a shorter list, `allowed_hosts`, `allowed_ports`, `allowed_dialects`, `allow_adhoc_connection: false` and `allow_call_literal_password: false` narrow the default. Unchanged for every default: caps and timeouts only lower, no `allow_execute` / `error_detail` / `read_only=false` from a call, no `execute` on an ad-hoc connection (a writing profile keeps working with connection fields in the call, as in Salt), the profile's password never goes to a retargeted host, and link-local and cloud-metadata targets (`169.254.0.0/16`, `fe80::/10`) are refused unless `allowed_hosts` lists them. A literal password in a call is stored by Salt in the job cache, event bus and minion debug log: prefer `sdb://`.
