New guide `docs/SALT_API.md`: a complete, tested salt-api example of every `sqlx` function for each database (PostgreSQL, MySQL, MariaDB run against real servers through a real master, minion and salt-api; Oracle and SQL Server written from the code and marked as not run), the request and response shapes including how an sqlx error appears over HTTP, a reference of what a caller can send by default, what is opt-in through `sqlx:_policy` and what can never be sent (with the real refusal text), how the operator tightens it, and eauth pinning (tested: a user pinned to `profile` is refused `sqlx.execute` and calls without a profile, but not a call that adds `host=` to an allowed profile). SPEC fixes found while testing: section 3.2 wrongly said that connection fields on a writing profile make `execute` fail with `[E_EXECUTE_DISABLED]` (it runs, as D16 decided), and `mariadb` is accepted as the dialect of a call but not in a profile (D10).
